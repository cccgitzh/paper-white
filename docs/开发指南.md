# 开发指南

## 架构

```
         ┌──────────────┐
         │   app.js     │  装配层：渲染管线、控件绑定、快捷键、导入导出
         └──────┬───────┘
    ┌───────────┼───────────┬────────────┬───────────┐
    ▼           ▼           ▼            ▼           ▼
crop.js    printer.js   geometry.js  perspective.js enhance.js
(交互)      (排版)       (旋转/检测)   (单应/约束)    (像素运算)
    └───────────┴───────────┴────────────┴───────────┘
                            ▼
                       state.js  (单一数据源 + 撤销栈)
                            ▼
                       utils.js  (纯工具)
```

- 全部为 IIFE 模块，挂在 `window.DC.*` 下，**不使用 ES Module**，
  因此 `file://` 直接双击也能跑（`import` 在 `file://` 下会被 CORS 拦截）。
- 加载顺序由 `index.html` 底部决定，不可随意调整：后面的模块依赖前面的模块。

## 渲染管线

```
原始图 Canvas
   │  geometry.buildBase(maxDim)     旋转 + 微调角度 + 纸色补边
   ▼
base Canvas（整图，未裁剪）
   │  perspective.warp(base, quad)   单应反查 + 双线性（无 quad 时跳过）
   ▼
裁剪后矩形
   │  enhance.process(canvas, rev)   纸底估计 → 归一化 → 色阶 → 锐化
   ▼
输出 Canvas → paint() 上屏 / toBlob 导出
```

**预览与导出走同一条管线**，只差 `maxDim`（预览 1200，导出 `null` = 原尺寸，
打印 2400）。任何改动都必须保证两个尺寸下参数一致，否则会出现"预览对、导出错"。

## 关键约定

| 约定 | 原因 |
|---|---|
| 参数只存在 `DC.state.params`，UI 通过 `syncControls()` 反向同步 | 避免 UI 与状态不一致 |
| `S.srcRev` 每次几何/图像变化自增，并参与背景缓存 key | 防止"尺寸相同但内容不同"命中旧缓存 |
| 裁剪框统一用归一化坐标 `[0,1]²` | 与画布像素尺寸解耦，预览/导出天然一致 |
| 不可逆操作前先 `DC.store.commit()` | 保证撤销栈能回退 |
| 任何阻塞操作都要 `setBusy(true/false)` | 大图处理会卡 1–3 秒，必须给反馈 |

## 常用调试手段

### 无头浏览器验证（本项目的标准做法）

```bash
# 生成注入脚本的临时页
node tools/test-page.mjs index.html _t.html "setTimeout(()=>{document.getElementById('btnSample').click()},200);
setTimeout(()=>{document.title='out='+DC.state.outW},1500);"

# 断言读 title
chrome --headless=new --window-size=1440,900 --virtual-time-budget=20000 \
       --dump-dom file:///abs/path/_t.html | grep -o "<title>[^<]*</title>"

# 视觉检查
chrome --headless=new --window-size=1440,900 --screenshot=shot.png file:///abs/path/_t.html
```

把断言结果写进 `document.title`，再用 `--dump-dom` 取出来，比 `console.log` 更好抓。

**注意**：`--window-size` 小于 500 px 时 Chrome 仍按 500 px 布局，截图会被裁切，
看起来像"溢出"，其实是测试假象。移动端请用 ≥500 px 验证。

### 性能观察

状态栏会显示最近一次预览渲染耗时。如果超过 200 ms，优先检查：

1. 背景缓存是否失效（`S.bgCache.size` 是否在暴涨）；
2. 是否在 `pointermove` 里同步做了 warp（应该只在小窗里做）。

## 修改检查清单

改完任何一个模块，至少确认：

- [ ] `node --check` 通过
- [ ] 示例图能正常加载、去底生效
- [ ] 进入裁剪 → 拖四个角 → 应用 → 输出边是否平直
- [ ] 打印弹窗能打开，`@page` 尺寸与所选纸张一致
- [ ] 撤销 / 重做各两次，参数与画面同步
- [ ] 桌面上双击 `index.html` 直接可用（不依赖服务器）
- [ ] `npm run build` 后 `dist/paper-white.html` 独立可运行

## 提交规范

```

```
