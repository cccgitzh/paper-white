# 算法说明

三个核心算法：去底（光照归一化）、倾斜检测（投影锐度）、透视裁剪（单应变换）。
本文只讲清楚「为什么这么做」和「哪里会踩坑」。

---

## 1. 去底：除以纸底亮度

### 问题

扫描件发灰，本质是**光照不均 + 纸底不是纯白**：
纸在左侧可能是 RGB(236,231,220)，到右下角变成 (215,208,190)，而文字始终在 40 左右。
直接用全局阈值或全局亮度拉伸，会把暗处的纸底拉成灰。

### 做法

对每个像素估计它「所在位置的纸底亮度」 `bg(x,y)`，然后

```
out = in × (255 / bg(x,y))
```

纸底（`in ≈ bg`）被拉到 255；墨迹（`in ≪ bg`）只被轻微提亮，仍保持深色。

### 估计 bg 的两个关键选择

**① 用「局部最大值」而不是「模糊」**

纸底永远比墨迹亮，所以取邻域内的最大值就能「跳过文字」拿到纸的亮度。
如果直接用均值模糊，遇到**大块深色区域**（粗黑标题、图章、照片），窗口里全是深色，
`bg` 会被拉到接近墨色，`255/bg` 变成 4~5 倍，**文字会被一并洗白**。

实现用单调递减队列做一维滑动最大值，先横后纵，复杂度 O(1)/像素：

```
for each row: deque 维护 (index, value) 单调递减 → 窗口最大值在队首
```

膨胀后再做一次盒式模糊（积分图 O(1)/像素）消除块状感，得到平滑的纸底估计。

**② 增益必须封顶**

即使做了膨胀，画面里的大面积深色物体（桌面、阴影）仍会让 `255/bg` 很大。
`f = min(255/bg, 2.4)` 把最大提亮倍数限死在 2.4 倍——纸底（200 左右）需要 1.27 倍，
留足余量；深色物体最多被提亮 2.4 倍，不会被洗成白。

### 彩色模式

黑白模式只处理亮度；彩色模式要**保留颜色**（红色印章、手写批注）。
若只用一个亮度 `bg` 去缩放 RGB，黄纸底洗完仍是米黄。

做法是对 R/G/B **分别**估一遍 `bg`，各自除各自的：

```
out_r = r × 255 / bg_r
out_g = g × 255 / bg_g
out_b = b × 255 / bg_b
```

这等价于「以纸底为白点的自动白平衡」：纸底三通道同时到 255（变纯白），
印章的红色通道仍显著高于蓝绿通道（仍是红的）。

之后再用一次按亮度比值的色阶映射压深文字，避免直接裁剪单通道导致偏色。

### 参数含义

- **背景范围**：膨胀半径，取短边的 3%~30%。半径要大于笔画宽度才能"跳过文字"，
  但不能大到跨越整块阴影。
- **黑场**：`out < 黑场 → 0`，压死浅灰噪点；给太大会吃掉笔画的抗锯齿边缘。
- **白场**：`out > 白场 → 255`，洗掉残留的浅灰。

## 2. 倾斜检测：投影锐度

### 原理

文字排成行时，**沿行方向做水平投影**，直方图会呈现「峰谷分明」的梳状分布；
角度偏了就糊在一起。所以找一个角度，让投影直方图最"尖锐"——用平方和衡量。

```
score(θ) = Σ_bin hist(bin)²        bin = round(y − x·tanθ)
```

遍历 θ ∈ [−12°, 12°]，取 score 最大的 θ；再在附近以 0.25° 精修。
施加到画布时取反号：`angle = −θ_best`。

### 踩过的两个坑

**坑 1：硬取整会让 0° 凭空占优**

`bin = round(...)` 在 θ = 0 时所有点恰好落在整数格上，没有任何分散；
其它角度总有半个像素的取整误差，把点洒到相邻 bin，分数天然偏低。
结果就是**不管图多斜都检测出 0°**。

解决：**软分箱**——把每个点按小数部分线性分给相邻两个 bin。

```js
const pos = y - x * tan;
const b0 = Math.floor(pos), fr = pos - b0;
hist[b0] += 1 - fr;
hist[b0 + 1] += fr;
```

**坑 2：稀疏采样制造虚假的行结构**

早期为了省时间，每隔 2 行取一个像素（`y += 2`）。细笔画只有 2~3 px 高，
抽样会与笔画形成**混叠**，人为造出一批"整齐的行"，同样把分数拉向 0°。

解决：不做稀疏采样，改为先把图缩到长边 900 px 再逐像素遍历——缩小时面积平均
本身就压掉了噪点，且不会产生混叠。

### 墨点提取

用 Otsu 阈值（类间方差最大）自动定阈值，避免固定 128 在灰底图上失效。
墨点少于 400 个时直接返回失败，提示用户手动调角度。

## 3. 透视裁剪：单应变换

### 数学

四个点确定一个单应矩阵 `H`（3×3，8 个自由度）：

```
[u, v, w]ᵀ = H · [x, y, 1]ᵀ ,   (X, Y) = (u/w, v/w)
```

每个点对给两个方程，四点共 8 个方程，用高斯消元（列主元）解 8 个未知数。

裁剪时求的是**反向**映射：目标矩形四角 `(0,0) (W,0) (W,H) (0,H)` →
源图四边形四点。然后遍历目标图每个像素，用 `H` 反查源图坐标，做双线性采样。

这样梯形区域被映射成矩形，纸边被真正拉直——而不是像矩形裁剪那样只切掉边角。

### 输出尺寸

```
outW = (上边长 + 下边长) / 2
outH = (左边长 + 右边长) / 2
```

取对边平均而不是取最大，梯形两侧的拉伸更均衡。

### 几何约束

拖拽时每次都要保证四边形合法，否则单应矩阵会退化（行列式趋零）导致画面撕裂：

1. 四点都在 `[0,1]²` 内；
2. 凸性：相邻三点的叉积符号一致（否则四边形自交）；
3. 最短边 ≥ 对角线 1.5%（否则接近退化）。

不满足就**丢弃这次位移**，手柄停在最后合法位置——比"夹到边界"更好理解，
也不会出现手柄被挤到墙角乱跳的情况。

### 快路径

如果四角本来就是轴对齐矩形（误差 < 0.6 px），直接 `drawImage` 裁切，
跳过一次重采样，既快又不损失锐度。

## 4. 旋转补边为什么不能填纯白

旋转后画布变大，四角需要填色。填纯白会被去底算法当成"纸底 255"，
邻域的 `bg` 被抬高，真实的灰纸底得不到应有的提亮，**图片边缘会留一圈灰边**。

做法：先取原图 75 分位亮度作为纸色（纸通常占画面主体），用它填边；
去底时这段补边与真实纸底亮度接近，会被一起归一化成白。
普通照片（亮度 < 175）仍用纯白补边，避免出现灰框。
